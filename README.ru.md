## ✨ Что это такое?

`work_schedule` — это **полностью клиентское веб‑приложение** для учёта нерегулярных рабочих смен (изначально сделано под график водителя автобуса, но подходит для любой почасовой работы). Открываете в браузере — и получаете полноценный табель и аналитическую панель: не нужен `npm install`, не нужен сервер, не нужна база данных. Все данные хранятся на вашем устройстве, приложение **полностью работает офлайн уже со второго открытия**, а по желанию — **синхронизируется со сквозным шифрованием и только по вашему нажатию** — между устройствами через Google Диск.

Приложение отвечает на три вопроса:

1. **Когда и сколько я работал?** → интерактивный календарь по месяцам
2. **Сколько я заработал?** → «табло» со счётчиками, которое пересчитывается автоматически по ставке
3. **Какие у меня закономерности?** → полноценная статистика с 10+ графиками

## 🧩 Возможности

| ⏱ **Автоматический пересчёт** | Часы, минуты и заработок пересчитываются мгновенно по формуле «ставка × время» — включая смены, переходящие через полночь, и фиксированные 20 минут «довоза до гаража», добавляемые к каждой смене (сейчас это константа в коде, а не настройка в интерфейсе). |
| 🟡 **Живые статусы смены** | Отдельные визуальные состояния для смен *в будущем*, *ещё не начавшихся* и *идущих сейчас* (доход по ним ещё не окончателен), обновляются фоновым «наблюдателем» каждую минуту. |

| 📊 **Статистика** | Лучший день/месяц, средняя длительность смены, эффективная почасовая ставка, соотношение будни/выходные, топ‑5 самых прибыльных смен, распределение по длительности смен, недельная динамика, самые частые времена начала смены, разбивка по автобусам и маршрутам. |
| 📈 **10+ живых графиков** | Столбчатые, линейные и кольцевые диаграммы по часам, заработку, накопительному доходу, дням недели и т.д. — на Chart.js, подгружается по требованию (см. «Производительность» ниже). |
| 🖼 **Фото к дню** | К любому дню можно прикрепить фото физического графика смен (автоматически сжимается прямо в браузере), с полноэкранным просмотром. |
| 🖨 **Печатный табель** | Одна кнопка формирует аккуратную печатную таблицу формата A4 — готово для сдачи в бухгалтерию. |
| 💾 **Импорт / экспорт** | Полный бэкап и восстановление в JSON, экспорт в CSV для таблиц, а также автоматический локальный бэкап перед рискованными действиями. |
| 📲 **Устанавливаемое PWA** | Добавление на главный экран Android/iOS с полноценной иконкой, отдельным окном без адресной строки и полной работой офлайн — см. ниже. |
| ☁️ **Синхронизация со сквозным шифрованием — по вашим правилам** | Необязательная синхронизация с Google Диском — данные шифруются паролем *до* отправки (Web Crypto API), поэтому прочитать их не может даже Google. ## ⚡ Офлайн и производительность

Приложение спроектировано так, чтобы открываться **мгновенно**, даже вообще без связи:

- **Service Worker (`sw.js`) кэширует всё приложение целиком** — весь HTML/CSS/JS и иконки — при первом посещении. Каждое следующее открытие отдаётся прямо с устройства, **без единого сетевого запроса**.
- **Никаких CDN‑зависимостей.** Chart.js, плагин подписей к нему и библиотека конфетти лежат локально в проекте (`js/vendor/`), а не подтягиваются с CDN при каждой загрузке — и даже так, грузятся лениво: в момент, когда вы реально открываете вкладку «Статистика» или сохраняете первую смену, а не заранее.
- **Единственное, что само по себе обращается в сеть — это нажатие кнопки «Синхронизировать».** Скрипт авторизации Google тоже не грузится до этого самого момента. Открытие приложения, просмотр календаря, ввод смен, статистика — ничего из этого не требует связи.
- **Версионирование против кэша**: каждый файл запрашивается со строкой `?v=X.Y.Z`, привязанной к `js/config/app-version.js` — поэтому обновление приложения на телефоне гарантированно подтягивает новые файлы, а не застревает на старой закэшированной копии. Поднятие версии (`bump-version.ps1`) обновляет её везде разом, включая список файлов внутри самого Service Worker.

## 🏗 Архитектура

Никаких фреймворков, сборщиков и `package.json` — только **чисто декомпозированный vanilla JS**, подключённый обычными тегами `<script>` в нужном порядке, и CSS, разложенный на пронумерованные «слои», из которых складывается дизайн‑система.

```
work_schedule/
├── index.html                  ← единственная точка входа, подключает все модули
├── sw.js                       ← Service Worker: офлайн-кэш (см. выше)
├── manifest.json                ← PWA-манифест (иконки, имя, режим standalone)
├── css/
│   ├── 00-tokens-and-reset.css     ← дизайн‑токены (цвета, отступы, шрифты)
│   ├── 01-header.css … 17-print-a4.css
│   └── ...                         ← 17 слоёв стилей, каскад по номерам
└── js/
    ├── init/            → загрузка приложения, инициализация, первый рендер, SW
    ├── data/             → загрузка/сохранение/валидация JSON и CSV, локальные бэкапы
    ├── shift/            → расчёт времени: минуты, смены через полночь, пересчёт
    ├── calendar/          → отрисовка сетки месяца, свайп‑навигация
    ├── day-modal/          → диалог редактирования дня + подсказки недавних времён
    ├── stats/               → все статистические агрегации
    ├── charts/               → построение графиков Chart.js, ленивая загрузка, стиль
    ├── heatmap/               → раскраска тепловой карты заработка
    ├── photo/                  → сжатие изображений, превью, лайтбокс
    ├── cloud/                   → OAuth Google Диска, AES‑шифрование, push/pull синхронизация
    ├── print/                     → генератор печатного табеля A4
    ├── modals/                     → общие модалки подтверждения/ввода
    ├── ui/                          → темы, тосты, вкладки, анимация LED‑счётчиков
    ├── config/                      → версия приложения, названия месяцев/дней (RU)
    ├── utils/                        → разбор дат, форматирование чисел и валюты,
    │                                    общий помощник ленивой подгрузки скриптов
    └── vendor/                        → локальные копии Chart.js, плагина подписей
                                          и конфетти (см. «Офлайн» выше)
```

**Философия:** каждый файл делает одну вещь — `compute-minutes.js` только считает минуты, `save-day-handler.js` только сохраняет день. Благодаря этому код легко проверить, легко передать другому разработчику и легко расширять без какой‑либо сборки.

## 🔐 Как устроена облачная синхронизация

Синхронизация **полностью опциональна**, построена по принципу «нулевого доверия» и **никогда не запускается сама**:

1. Вы входите через Google (OAuth, доступ только к вашему собственному Диску, запрашивается только по нажатию «Синхронизировать»).
2. Придумываете пароль — он никогда не покидает устройство.
3. Из пароля выводится ключ (`derive-key.js`), которым график **шифруется по AES** (`encrypt-for-cloud.js`) перед загрузкой.
4. На Google Диске хранится только непрозрачный зашифрованный блок; расшифровка происходит локально (`decrypt-from-cloud.js`) после скачивания.
5. Перед тем как заменить облачную копию *меньшим по объёму* локальным набором данных, приложение сравнивает количество смен с обеих сторон и спрашивает подтверждение — так свежая установка или очистка данных браузера никогда не сотрёт молча месяцы синхронизированной истории.
6. Приложение запоминает и показывает, **когда синхронизация в последний раз прошла успешно** — вы всегда знаете, уехали ли последние правки в облако.

Если пароль забыт — зашифрованную резервную копию не сможет прочитать никто, включая само приложение.

## 🚀 Быстрый старт

Установка не требуется.

```bash
# Скачайте или склонируйте репозиторий и запустите локальный сервер
# (нужен для корректной работы Service Worker и OAuth Google Диска —
# браузеры ограничивают оба API адресами http(s)://, file:// не подойдёт):
python3 -m http.server 8000
# → http://localhost:8000
```

В комплекте есть готовый помощник:

```powershell
.\start-localhost.ps1
```

**Готово.** Укажите ставку в шапке, кликните по дню, внесите смену — календарь, табло и статистика обновятся мгновенно. Установите на главный экран телефона — получите полноценную иконку приложения и работу полностью офлайн.

## 📦 Данные и приватность

- Данные хранятся **локально в первую очередь**, в `localStorage` — приложение всегда полностью работает офлайн.
- Ничего никуда не отправляется, пока вы явно не нажмёте кнопку «Синхронизировать» — никакой фоновой или автоматической сетевой активности нет.
- В любой момент можно экспортировать/импортировать весь график в JSON (`💾 Сохранить JSON` / `📂 Загрузить JSON`) или выгрузить CSV для Excel/Google Таблиц.
- Кнопка **«🛡️ Быстрый бэкап»** создаёт локальную копию с меткой времени перед любым рискованным действием.

## 🛠 Технологии

| Слой | Выбор | Почему |
|---|---|---|
| Интерфейс | Vanilla HTML/CSS/JS | Без сборки, открывается из одного файла, легко разместить где угодно |
| Офлайн | Service Worker + Cache API | По-настоящему офлайн-first, мгновенные повторные открытия |
| Графики | [Chart.js](https://www.chartjs.org/) + плагин подписей данных | Лёгкий вес, без привязки к фреймворку, лежит локально и грузится лениво |
| Хранение | `localStorage` + Web Crypto API | Работает офлайн, приватность по умолчанию |
| Синхронизация | Google Drive API (OAuth), только по действию пользователя | Бесплатно, повсеместно, не нужен собственный сервер |
